Linux 权限说明

用户与用户组

  • root（UID 0） ：超级用户，拥有系统最高权限，绕过绝大多数权限检查。
  • 系统用户（UID 1–999） ：为服务进程创建的伪用户，如 www-data、mysql、nobody。
  • 普通用户（UID ≥ 1000） ：日常登录用户，权限受 UGO 模型约束。

每个用户可属于一个主组和若干附加组。id 命令可查看当前用户的 UID、GID 及附加组信息：

文件基础权限

每个文件有三组权限位，分别对应属主（owner）、属组（group）、其他用户（other）：

位置 含义
第 1 位 文件类型（-普通文件，d目录，l符号链接）
第 2-4 位 属主权限（rwx）
第 5-7 位 属组权限（rwx）
第 8-10 位 其他用户权限（rwx）
  • r：读权限。对文件表示可读取内容，对目录表示可列出其中的文件名。
  • w：写权限。对文件表示可修改内容，对目录表示可增删其中的文件。
  • x：执行权限。对文件表示可执行，对目录表示可进入（cd）。

权限也可用八进制表示，例如 rwxr-xr-x = 755，rw-r--r-- = 644。

特殊权限位

除 rwx 外，Linux 还有三种特殊权限位：

特殊位 作用对象 字符标识 八进制 含义
SUID 可执行文件 s在属主 x 位 4000 执行时以文件属主身份运行
SGID 可执行文件/目录 s在属组 x 位 2000 执行时以属组身份运行；对目录则使新文件继承目录属组
SBIT 目录 t在其他用户 x 位 1000 目录内文件仅文件属主和 root 可删除（如/tmp）

passwd 属主为 root，且属主权限位为 rws，即设置了 SUID。这意味着任何用户执行 passwd 时，进程的有效 UID（EUID）会被设为 root，从而能写入 /etc/shadow。

/tmp 的其他用户权限位为 rwt，即设置了 SBIT，保证用户只能删除自己创建的临时文件。

SUID 提权

提权原理

SUID 提权的核心是：当一个设置了 SUID 位的二进制文件的属主是 root 时，普通用户执行它所得到的进程 EUID 为 root。如果该二进制本身存在可被利用的功能（如可执行外部命令、可读写任意文件），就能借此获得 root 权限。

SUDO 提权

提权原理

sudo 允许管理员在 /etc/sudoers 中授权某些用户以特定身份执行特定命令。sudo 需要有一个普通用户权限的 shell，因为 web 用户的权限通常较低（如 www-data 用户），且可能缺乏交互式终端或环境完整性。

Cron 提权

提权原理

cron 是 Linux 的定时任务服务。系统级 cron 任务定义在 /etc/crontab、/etc/cron.d/*、/etc/cron.{hourly,daily,weekly,monthly}/ 中，常以 root 身份执行。若任务脚本存在以下问题，即可被利用：

  • 以 root 身份执行的脚本对低权限用户可写
  • 脚本中使用通配符展开（如 tar *）
  • 脚本调用的程序路径可被覆盖

经典内核漏洞

CVE-2016-5195 - DirtyCow

影响 Linux 内核 2.6.22 至 4.8.3，几乎覆盖 2007–2016 年间所有发行版。利用竞态条件使只读内存映射可写，可覆盖 /etc/passwd 或映射 suid 程序代码段注入 shellcode。

CVE-2026-31431 - Copy Fail

内核加密子系统的 algif_aead 用户态接口（crypto/algif_aead.c），在处理 recvmsg 拷贝失败时未正确回滚状态，导致内核内存破坏。

Capability 提权

提权原理

Linux capabilities 将 root 权限拆分为若干细粒度能力（如 cap_setuid、cap_dac_read_search）。若程序被赋予了危险 capability，可被用于提权。

cap_dac_read_search 绕过文件读权限检查
cap_dac_override 绕过文件读写权限检查
cap_setfcap 给任意文件赋予 capability
cap_sys_admin 接近 root 的通用能力（mount、namespace 等）

LD_PRELOAD 提权

提权原理

LD_PRELOAD 是 Linux 系统的环境变量，允许用户指定在程序运行前优先加载的动态链接库（.so 文件）。动态链接器在加载程序时，会优先加载 LD_PRELOAD 指定的库，覆盖程序原本依赖的库函数。通过劫持目标程序调用的关键函数（如 getuid、strcmp 等），攻击者可注入恶意代码实现提权。

LXD 容器提权

提权原理

LXD（Linux Container Daemon）是一种基于 LXC 的系统容器管理器，通过 REST API 提供容器管理能力。其提权漏洞的核心在于特权容器（Privileged Container）的配置缺陷：

  • 特权容器特性： 当容器以 security.privileged=true 启动时，容器内的 root 用户直接映射到宿主机的 root 用户，绕过了 Linux 用户命名空间的隔离机制
  • 文件系统挂载： 通过 lxc config device add 命令将宿主机根目录（/）挂载到容器内（如 /mnt/root），容器内可直接读写宿主机的文件系统，实现权限逃逸

UDF提权简介

提权原理

UDF（User Defined Function，用户自定义函数）是 MySQL / MariaDB 提供的扩展机制，允许用户用 C/C++ 编写自定义函数，编译为共享库（.so）后加载到数据库中作为 SQL 函数调用。若 MySQL 以 root 身份运行，且攻击者拥有 MySQL 高权限账户（或通过 SQL 注入获得写权限），即可上传恶意 .so，注册一个调用 system() 的 UDF，从而以 root 身份执行任意系统命令。利用条件如下：

  • MySQL 服务以 root 或较高权限用户运行
  • secure_file_priv 未限制导出路径，或限制路径可写（MySQL 5.7+ 默认 /var/lib/mysql-files/）
  • 知道 MySQL 插件目录路径（@@plugin_dir）
