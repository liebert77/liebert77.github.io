Linux提权小结

发表于2026-07-26|技术杂项
|总字数:5.7k|阅读时长:21分钟|浏览量:

本文仅供安全研究、授权渗透测试、CTF 竞赛与防御教学使用。未经授权对他人系统实施提权攻击属于违法行为。

引言

Linux 提权（Privilege Escalation）是渗透测试中的核心环节。攻击者获得初始 foothold 后通常只有低权限 shell（如 www-data、nobody），需要将权限提升到 root 才能实现凭据窃取、横向移动和持久化控制。

本文将 Linux 提权技术分为五大类，按内核漏洞 → 配置错误 → 特权滥用 → 服务利用 → 环境劫持的逻辑展开，力求分类清晰、覆盖全面。

分类 核心思路 代表技术
内核漏洞 利用内核 CVE 直接改写进程凭证 DirtyCow、DirtyPipe
配置错误 利用管理员配置不当 SUID滥用、Cron劫持、可写passwd
特权滥用 利用已有的 sudo/capability 权限 sudo提权、Capability提权
服务利用 利用以 root 运行的服务漏洞 UDF提权、NFS提权
环境劫持 劫持程序运行环境 PATH劫持、LD_PRELOAD劫持

一、Linux 权限体系基础

理解提权的前提是理解 Linux 的权限模型。Linux 采用 UID/GID 体系区分用户身份，通过 UGO（User/Group/Other）模型控制文件访问。

1.1 用户角色

角色 UID 说明
root 0 超级用户，绕过绝大多数权限检查
系统用户 1–999 服务进程专用账户，如 www-data、mysql、nobody
普通用户 ≥1000 日常登录用户，受 UGO 模型约束

每个用户可属于一个主组和若干附加组。id 命令可查看当前用户的 UID、GID 及附加组信息：

1.2 文件基础权限

每个文件有三组权限位，分别对应属主（owner）、属组（group）、其他用户（other）：

位置 含义
第 1 位 文件类型（- 普通文件，d 目录，l 符号链接）
第 2-4 位 属主权限（rwx）
第 5-7 位 属组权限（rwx）
第 8-10 位 其他用户权限（rwx）
  • r：读权限。对文件表示可读取内容，对目录表示可列出其中的文件名。
  • w：写权限。对文件表示可修改内容，对目录表示可增删其中的文件。
  • x：执行权限。对文件表示可执行，对目录表示可进入（cd）。

权限也可用八进制表示，例如 rwxr-xr-x = 755，rw-r--r-- = 644。

1.3 特殊权限位

除 rwx 外，Linux 还有三种特殊权限位：

特殊位 作用对象 字符标识 八进制 含义
SUID 可执行文件 s 在属主 x 位 4000 执行时以文件属主身份运行
SGID 可执行文件/目录 s 在属组 x 位 2000 执行时以属组身份运行；对目录则使新文件继承目录属组
SBIT 目录 t 在其他用户 x 位 1000 目录内文件仅文件属主和 root 可删除（如 /tmp）

passwd 属主为 root，且属主权限位为 rws，即设置了 SUID。这意味着任何用户执行 passwd 时，进程的有效 UID（EUID）会被设为 root，从而能写入 /etc/shadow。

/tmp 的其他用户权限位为 rwt，即设置了 SBIT，保证用户只能删除自己创建的临时文件。

二、内核漏洞提权

2.2 经典内核漏洞

CVE-2016-5195 — DirtyCow

影响 Linux 内核 2.6.22 至 4.8.3，几乎覆盖 2007–2016 年间所有主流发行版。利用竞态条件（race condition）使只读内存映射变为可写，进而覆盖 /etc/passwd 或篡改 SUID 程序代码段注入 shellcode。

CVE-2022-0847 — DirtyPipe

影响 Linux 内核 5.8 至 5.16.10。利用管道缓冲区标志未被正确重置的缺陷，可覆写任意只读文件（包括 /etc/passwd）或覆盖 SUID 二进制代码段。

CVE-2026-31431 - Copy Fail

内核加密子系统的 algif_aead 用户态接口（crypto/algif_aead.c），在处理 recvmsg 拷贝失败时未正确回滚状态，导致内核内存破坏。

内核 Exploit 可能导致系统崩溃，生产环境需谨慎。务必先确认内核版本、位数和补丁状态。

三、配置错误提权

配置错误提权不依赖内核漏洞，而是利用管理员配置不当或安全意识缺失。即使系统补丁完善，这类路径依然有效，是实际渗透中最常见的提权方式。

3.1 SUID 提权

提权原理

当一个设置了 SUID 位的二进制文件属主为 root 时，普通用户执行它所得到的进程 EUID 即为 root。若该二进制本身具备可被利用的功能（如可执行外部命令、可读写任意文件），攻击者便可借此获得 root 权限。

3.2 Cron 定时任务提权

提权原理

cron 是 Linux 的定时任务服务。系统级 cron 任务定义在 /etc/crontab、/etc/cron.d/*、/etc/cron.{hourly,daily,weekly,monthly}/ 中，通常以 root 身份执行。若任务脚本存在以下任一问题，即可被利用：

  • 以 root 身份执行的脚本对低权限用户可写

  • 脚本调用的程序路径可被覆盖

3.3 通配符注入提权

提权原理

当 cron 任务或脚本中使用通配符（如 tar *、rsync *）时，攻击者可创建特殊命名的文件，使其被通配符展开后转化为命令参数，从而注入任意命令。

3.4 可写 /etc/passwd 提权

提权原理

/etc/passwd 在某些配置不当的系统上对普通用户可写。passwd 文件格式为 username:password:UID:GID:info:home:shell，其中密码字段存放哈希值。若该文件可写，直接追加一个 UID 为 0 的用户记录即可获得 root 权限。

3.5 NFS 提权

提权原理

当 /etc/exports 中以 no_root_squash 挂载目录时，NFS 客户端的 root 用户在共享目录中仍以 root 身份写文件。

四、特权滥用提权

利用已有特权（sudo 规则、Linux Capabilities）进行权限提升。这类方法不依赖内核漏洞，而是利用管理员授予的过度权限——本质上是”合法权限的不当使用”。

4.1 SUDO 提权

提权原理

sudo 允许管理员在 /etc/sudoers 中授权某些用户以特定身份执行特定命令。如果授权了可被滥用的程序（如 find、perl、python、vim），攻击者可通过这些程序逃逸出受限环境获得 root shell。

sudo 提权的前提是拥有一个普通用户权限的交互式 shell。Web 服务用户（如 www-data）通常权限较低且缺乏完整的终端环境，需要先提权到普通用户再利用 sudo。

4.2 Capability 提权

提权原理

Linux capabilities 将传统的 root 全能权限拆分为若干细粒度能力（如 cap_setuid、cap_dac_read_search）。若某个程序被赋予了危险 capability，攻击者便可借此实现提权。

常见危险 Capability：

Capability 危害
cap_setuid 任意切换 UID，直接提权 root
cap_dac_read_search 绕过文件读权限检查
cap_dac_override 绕过文件读写权限检查
cap_setfcap 给任意文件赋予 capability
cap_sys_admin 接近 root 的通用能力（mount、namespace 等）
cap_sys_ptrace 注入其他进程

五、服务利用提权

利用以 root 身份运行的服务（如 MySQL、LXD）的配置缺陷或功能特性实现提权。这类方法的关键在于：服务本身以高权限运行，且攻击者能够利用其功能执行系统命令或访问宿主文件系统。

5.1 UDF 提权

提权原理

UDF（User Defined Function，用户自定义函数）是 MySQL / MariaDB 的扩展机制，允许用户用 C/C++ 编写自定义函数，编译为共享库（.so）后加载到数据库中作为 SQL 函数调用。若 MySQL 以 root 身份运行，且攻击者拥有高权限数据库账户（或通过 SQL 注入获得写权限），即可上传恶意 .so 文件，注册一个调用 system() 的 UDF，从而以 root 身份执行任意系统命令。

利用条件：

  • MySQL 服务以 root 或较高权限用户运行
  • secure_file_priv 未限制导出路径，或限制路径可写（MySQL 5.7+ 默认 /var/lib/mysql-files/）
  • 知道 MySQL 插件目录路径（@@plugin_dir）

5.3 LXD 容器提权

提权原理

LXD（Linux Container Daemon）是基于 LXC 的系统容器管理器。其提权的核心在于特权容器（Privileged Container）的配置缺陷：

  • 特权容器特性：当容器以 security.privileged=true 启动时，容器内的 root 用户直接映射到宿主机的 root 用户，绕过了 Linux 用户命名空间的隔离机制。

六、环境劫持提权

通过修改程序运行环境（PATH 变量、动态链接库）使目标程序加载攻击者的恶意代码，从而在高权限上下文中执行任意命令。这类方法不需要内核漏洞或配置错误，而是利用程序对运行环境的信任。

6.1 PATH 提权

提权原理

若某个 SUID / sudo / cron 程序调用了未使用绝对路径的外部命令，攻击者可通过修改 PATH 环境变量让程序优先加载自定义的恶意版本。

6.2 LD_PRELOAD 提权

提权原理

LD_PRELOAD 是 Linux 动态链接器的环境变量，允许用户指定在程序运行前优先加载的动态链接库（.so 文件）。当程序启动时，动态链接器会先加载 LD_PRELOAD 指定的库，从而覆盖程序原本依赖的库函数。攻击者通过劫持关键函数（如 getuid、strcmp 等），可在目标程序的高权限上下文中注入并执行任意代码。

利用条件：sudo 配置中设置了 env_keep += LD_PRELOAD（保留 LD_PRELOAD 环境变量）。

八、防御与缓解

8.1 最小权限原则

  • 服务账户使用最小权限，避免不必要的 sudo 规则
  • Web 服务（www-data、nginx）不加入特权组
  • 谨慎授予 NOPASSWD sudo 规则，禁止通配符命令
  • 定期审计 /etc/sudoers 和 /etc/sudoers.d/

8.2 SUID 与 Capability 加固

  • 定期扫描 SUID 文件，与基线对比：
  • 移除不必要的 SUID 位（chmod u-s）
  • 审计 capabilities 分配，仅对必要程序授予
  • 禁用不必要的 setcap 权限

8.3 Cron 与服务加固

  • cron 脚本使用绝对路径
  • cron 脚本权限设为 700，仅 root 可写
  • 避免在 cron 中使用通配符（*）
  • NFS 挂载禁用 no_root_squash，使用 root_squash
  • MySQL 不以 root 身份运行，限制 secure_file_priv

8.4 内核与补丁管理

  • 保持内核版本最新，关注本地提权 CVE
  • 使用 unattended-upgrades 自动安装安全补丁
  • 容器环境也需更新内核（不要依赖容器隔离）
  • 高风险服务器建立快速回滚机制

8.5 监控审计

  • 配置 auditd 审计 SUID 执行和 sudo 使用
  • 监控 /etc/passwd、/etc/shadow、/etc/sudoers 修改
  • 使用 AIDE / Ossec 做文件完整性监控
  • 集中收集日志，配置异常告警

总结

Linux 提权是一个多层次的技术体系，实战中遵循以下方法论：

  1. 先收集，再利用 — id、uname -a、sudo -l + LinPEAS 全面收集
  2. 内核优先 — 使用 linux-exploit-suggester 识别漏洞，选择稳定 Exploit
  3. 配置兜底 — 补丁完善时重点查 SUID 程序、Cron 任务、服务权限、NFS 配置
  4. 特权利用 — sudo -l 有可滥用程序查 GTFOBins，getcap 有危险 capability 则直接提权
  5. 环境劫持 — PATH 劫持和 LD_PRELOAD 劫持利用程序环境缺陷
  6. 服务逃逸 — MySQL UDF、LXD 容器逃逸利用高权限服务

防御核心是最小权限原则和配置加固：定期审计 SUID/Capability/sudo 规则、保持内核补丁更新、部署文件完整性监控，可有效收敛提权攻击面。
